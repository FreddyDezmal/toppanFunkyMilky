## What the release does

**Patrons** register and sign in; order 1–10 milkshakes, each with its own flavour, consistency and topping; see
read-only prices per drink, discount, VAT (15 %) and total; choose a pickup restaurant and time; pay online with
Paystack (test mode) – the order is confirmed only after the server verifies the payment; receive one combined order
confirmation and receipt email; see their order history; cancel a paid order before pickup (10 % fee, refund through
Paystack) or answer a restaurant's request to cancel (full refund).

**Managers** maintain flavours, consistencies, toppings and their prices (with history; changes affect new orders
only), restaurants, settings (drinks per order, VAT, pickup window, refund fee, maximum discount) and discount tiers;
find orders and ask a patron to cancel; see refunds needing attention and every email (with resend); view reports
(orders per period, trends by weekday/week/month, CSV export) and the Audit Lookup (who changed what from what to
what, sign-in events), with patron details masked.

**Security and operations:** one origin for site and API (no CORS); session and anti-forgery cookies Secure, HttpOnly,
SameSite=Strict; CSRF on every write; deny-by-default authorisation; rate limits; append-only audit trail; HSTS and a
strict Content-Security-Policy; sign-in keys encrypted in the database; daily encrypted backups with an automatic
restore test; health monitoring every 6 hours with email alerts; deployments only by hand from a release tag whose CI
run passed.

## Known limitations

- Free hosting: sleeps after 15 minutes idle (first request about a minute); background work pauses while asleep;
  monitoring every 6 hours, not continuous.
- Paystack test mode only (D-1); email delivered only to the Resend account's address (E-1).
- Frequent-customer discounts switched off until rates are supplied (Q-01–Q-04).
- No email confirmation or password reset; no "Collected" status; data-retention policy not decided (Q-14).
- Code not reviewed by a second developer (D-9).

## Upgrading / rolling back

Deploy: Actions → Deploy → tag. Rollback: the same with the previous tag (`v1.0.1`); the database is never rolled back
(operations guide §9). No migrations differ between v1.0.1 and v1.0.2.
