## What changed

v1.1.0 is a **visual redesign and usability release**. The backend, the database, the API and its contracts are
unchanged: no migrations, no new settings, no new secrets, and no new dependencies.

The audit, the approved design (decisions D-R1 to D-R9, 22 Nov 2026) and the stage log are in
[`docs/redesign/2026-11-22_design-audit-proposal.md`](../redesign/2026-11-22_design-audit-proposal.md).

| Area | Change |
| --- | --- |
| Look | Cream, chocolate, raspberry, strawberry and pistachio palette with every text pairing measured for WCAG AA. Fraunces and Plus Jakarta Sans fonts (SIL Open Font License), self-hosted, so the CSP is unchanged. Original SVG illustration and icons, with no third-party artwork. |
| Header | Sticky header with a skip link. On phones the links fold behind one **Menu** button. The "Development build" footer is gone. The header no longer jumps while the session loads, and protected pages show a placeholder instead of a blank screen. |
| Home | New landing page: "Your Milkshake. Your Rules.", **Build Your Milkshake**, how it works, and (for signed-in patrons) the live menu with current prices before VAT. The build-time test text and the System status card are gone from the public page. |
| Log in, registration, account | Split screen on wider screens. Same fields, validation, messages and security. My account has next steps. New "Page not found". |
| Ordering | **−/+** quantity. Flavour, consistency and topping as cards with their current fees. A summary beside the builder that stays in view; on phones, a bar at the bottom with the total and Continue. Restaurant cards. Review with a place-order panel. The stale "payment is not available yet" and "pickup times are provisional" notes are removed. |
| Orders | My orders as cards on phones and a list on wider screens, with order and payment status as labelled badges. The order page has payment beside the price, and cancellation and refunds set apart. |
| Management | Grouped sidebar, or a **Sections** button on phones. An overview of today's orders, refunds needing attention, email counts and the system status (moved here from the home page). On phones every table becomes one card per row, with all actions visible. |
| Accessibility | Tab title on every page; focus moves to the new page's heading. Keyboard-friendly choice cards (one Tab stop per group, arrow keys). Visible focus ring. Reduced motion respected. Meaningful text at least 14 px. The chart scroll area is keyboard-reachable. "Send again" names start with their visible words. |

**Unchanged by design:**
- API calls and contracts;
- server-authoritative pricing, quantity limits, pickup validation and order idempotency;
- Paystack test-mode payment, verification, webhooks, refunds and cancellation fees;
- report calculations and exports;
- authentication, CSRF, CSP and security headers;
- each patron sees only their own orders.

Restaurant addresses show as stored (decision D-R6 c).

## Known limitations

As for v1.0.2: free hosting sleeps after 15 minutes; Paystack test mode only; email only to the approved address;
discounts switched off. In addition:
- The landing-page menu shows only to signed-in patrons, because the menu API is patron-only and no backend change was
  made for this release.
- The fonts are served with the site's normal revalidation caching rather than the year-long caching used for hashed
  assets: about 64 KB, checked again on each visit, without re-downloading when unchanged.

## Deploying and rolling back

1. Confirm the CI run for the release commit on `main` is green.
2. Tag the release commit and push the tag: `git tag v1.1.0 <commit>` then `git push origin v1.1.0`.
3. Actions → **Deploy** → Run workflow → tag `v1.1.0`. The workflow checks that the tag is on `main` and that its CI
   passed.
4. Run `node tools/deploy/verify-production.mjs https://milkyshaky.onrender.com` and the browser smoke test
   (operations guide).
5. **Rollback:** the same Deploy workflow with tag `v1.0.2`. No migrations differ between v1.0.2 and v1.1.0, so the
   database is untouched either way.
